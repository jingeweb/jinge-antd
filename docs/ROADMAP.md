# Jinge Antd：PC 中台组件范围与交付顺序

## 已确认边界

面向 PC 中台系统，以常见管理系统的查询、编辑、列表、详情、导航与反馈流程覆盖“80%”。允许重构、破坏性 API 调整，并同步迁移示例和测试。中文文档；现代桌面浏览器与基本窄屏适配。首轮不做 SSR、移动端专用交互、RTL、Pro 系列、设计规范站点。

新增任何外部依赖必须先停下来向用户说明用途、替代方案和成本并获确认。现有依赖可继续使用。框架无法自然表达的能力暂缓，记录最小复现和受影响能力，不直接修改 Jinge/Compiler。

参考（组件级 API/交互，而非逐项移植）：

- https://ant.design/components/overview/
- https://element-plus.org/en-US/component/overview.html
- https://www.radix-ui.com/primitives/docs/overview/accessibility

## 公共契约

- 组件、Props 类型具名导出；尺寸统一 sm / md / lg，默认 md。
- 保留 Jinge 的 on:事件、slot:插槽和 ref/expose 方式，不模拟 React hooks 或克隆 children。
- 输入控件明确 value/defaultValue、change、清空值语义；初始化后不支持隐式切换受控模式，文档必须明确。
- 原生 id/name/label/aria 与 focus/blur 根据组件需要开放；键盘、禁用、焦点恢复为基础能力。
- className/style 为基本样式入口；基础样式和 CSS 变量应在无 Tailwind 的消费项目中成立。
- 生命周期管理定时器、事件、observer、订阅与异步过期结果。
- 组合组件通过公开 context/ref/slot API 实现；不能自然实现的复杂 children 变换单独记录。

## 每组件完成条件

1. 范围/API/空值/静态属性和限制明确。
2. 实现及类型通过检查；新增/修改组件有独立普通测试。
3. 交互、焦点、布局或浏览器原生行为有 e2e；正常测试不得新增失败。
4. 相关已知问题回归转绿；未修复问题继续明确标记，禁止删除或反向断言。
5. site 中有实际使用示例、来自同一文件的源码、属性/事件/插槽/方法与限制。
6. 更新交付记录、迁移说明、框架问题记录；不以壳组件/占位页面标记完成。
